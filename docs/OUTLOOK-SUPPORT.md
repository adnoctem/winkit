# Outlook script support

The `scripts/Office` scripts automate Outlook through its COM object model and
data-file repair utilities. This page documents the supported Outlook
versions, operational requirements, and the testing strategy.

## Support matrix

| Script                       | Minimum Outlook | Notes                                                                               |
| ---------------------------- | --------------- | ----------------------------------------------------------------------------------- |
| `New-OutlookArchive.ps1`     | 2007 (12)       | Unicode PST creation via `NameSpace.AddStoreEx`.                                    |
| `Optimize-Outlook.ps1`       | 2007 (12)       | Reads transport headers via `Item.PropertyAccessor`, which Outlook 2007 introduced. |
| `Repair-OutlookDataFile.ps1` | 2007 (12)       | Discovers `SCANPST.EXE`/`SCANOST.EXE` from Office 12 installations onward.          |

All scripts fail fast with a clear error when the installed Outlook is older
than version 12, so an unsupported client never results in silent partial
processing.

## Operational requirements

- **32-bit PowerShell**: Outlook 2007 is 32-bit only. 64-bit PowerShell cannot
  create the `Outlook.Application` COM server (in-process, registered only in
  the 32-bit view). Use Windows PowerShell 5.1 (x86) or 32-bit PowerShell 7 to
  automate Outlook 2007-era clients. Office 2010 64-bit and newer can be
  automated from 64-bit PowerShell.
- **Interactive profile**: the scripts log on to the MAPI profile of the
  logged-on user. They are not suitable for the SYSTEM account and are not
  Server Core compatible.
- **Outlook Object Model Guard**: Outlook 2003-2007 may prompt when a program
  sends mail or accesses address books and recipient details. The winkit
  scripts avoid those operations (no `Send`, no `Recipients`, no address-book
  access), so no security prompts are expected.
- **Dry run first**: every script supports `-DryRun` and `-PassThru`. Run a
  dry run against a disposable test profile before touching a real mailbox.

## Testing

### Tier 0 - logic tests (CI, no Outlook)

Pure parsing logic (transport Message-ID extraction) lives in the PSFoundation
module and is covered by Pester tests in the PSFoundation repository. Run
`.\winkit.ps1 test` for the winkit-side test suite; run the PSFoundation suite
in the PSFoundation repository for module logic.

### Tier 1 - integration tests (needs Outlook)

`.\winkit.ps1 test -Outlook` runs `tests/Office/Outlook.Integration.Tests.ps1`
against a **disposable Outlook profile whose default store is a scratch PST**.
The synthetic mail is generated by `scripts/Office/New-TestOutlookMessage.ps1`
(deterministic subjects, Message-IDs, date ranges, and seeded duplicates), so
the personal mailbox is never touched.

See `tests/Office/README.md` for the 2007 test-machine setup, the profile
recipe, and the run/assert/teardown steps.

### Fixture generation

`New-TestOutlookMessage.ps1` fabricates mail items through the Outlook object
model. Transport headers (Message-ID) are injected best-effort through
`PropertyAccessor`; install the free-for-personal-use Redemption component
(`Redemption.RDOSession`) for guaranteed header writes, including backdated
`ReceivedTime` values.
